Context, route bases only for now:
- db free testing, input is the pre-constructed output of the 'rows' of the db query and a file with the 'now' to bypass issues with actual now
- the 'rows' are then sent through the interpreter code and the output is compared with the expected output file
- then the output of the interpretation is sent through coordinator.py and again compared with the expected output of that one, as the coordinator output is used in the actual entity/sensor

Install:
run in /tests .... 
	pip install requirements.txt
Note: sadly, this is outside of a HA container, and requires the install of homeassistant

run from the component root (where /tests and /custom_components reside):
	pytest tests/test_static_cases.py --tb=short
	
Ananlyse the output in tests/case_route/results.txt


Fixtures (tests/fixtures):
- real feeds cut down to a few routes, 24 to 88 KB each: gvb, palmbus, sncf (with trip updates and alerts), sncf-journeys, tao-journeys
- manifest.json in each says where the bytes came from, what was kept and why; sncf also carries scenarios.json, the journeys its entities make testable
- build_fixture.py cuts any static zip down to named routes, a few trips per stop pattern
- capture_rt.py freezes a static + trip updates + alerts capture, SNCF by default, any feed with --static/--trip-updates/--alerts
- a test pins its clock at the manifest's captured_at (freezegun or ha_stub.freeze), so the data never has to be shifted to today
